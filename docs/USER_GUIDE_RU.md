# DashSpec — руководство пользователя

Документ для **людей, которые открывают отчёты в браузере**: смотрят диаграммы, крутят фильтры, кликают по сегментам. Без программирования.

Если нужно **написать** отчёт или поднять Host — см. [HOWTO_RU.md](HOWTO_RU.md).

---

## 1. Что такое DashSpec

**DashSpec** — это способ показывать operational-дашборды из SQL Server:

1. Автор описывает отчёт текстом (файл `.dashspec` в git).
2. Служба **DashSpec Host** читает описание и рисует интерактивную страницу в браузере.
3. Ты открываешь URL, выбираешь период и измерения — карточки обновляются сами.

Тебе не нужно знать SQL, чтобы пользоваться экраном. Полезно понимать только: **фильтры сужают данные**, а **клик по сегменту** часто ставит такой же фильтр.

---

## 2. Как попасть на отчёт

| Шаг | Что сделать |
|-----|-------------|
| 1 | Открыть адрес Host (пример: `http://сервер:5295/`). Порт и хост задаёт администратор. |
| 2 | Если спросили ключ — страница `/access` или закладка с параметром (см. ниже). |
| 3 | Вверху выбрать **отчёт** из списка (catalog), если их несколько. |
| 4 | При необходимости переключить **вкладку** (Overview / Detail / …). |

### Доступ по ключу

На защищённом Host пустой экран или редирект на `/access` — норма.

1. Открой `/access`.
2. Введи API-ключ (выдаёт администратор).
3. Host сохранит cookie примерно на **30 дней**.

Альтернативы (для скриптов / разовой закладки):

- заголовок `X-Api-Key`;
- один раз `/?api_key=…` — ключ уйдёт в cookie, из адресной строки лучше убрать.

`GET /health` обычно **без ключа** — только проверка, что служба жива.

## 3. Устройство экрана

Типичная страница:

```text
┌─ шапка ─────────────────────────────────────────────┐
│  название отчёта · выбор отчёта (catalog) · вкладки │
├─ панель фильтров (toolbar) ─────────────────────────┤
│  Период | Программа | Локация | … · чипы выбора     │
├─ сетка карточек ────────────────────────────────────┤
│  ┌ card ──┐  ┌ card ──┐                             │
│  │ title  │  │ title  │                             │
│  │ chart  │  │ chart  │                             │
│  └────────┘  └────────┘                             │
└─────────────────────────────────────────────────────┘
```

| Элемент | Зачем |
|---------|--------|
| **Catalog / отчёт** | Разные `.dashspec` на одном Host (например soak и stakeholder). |
| **Вкладки** | Разные наборы карточек внутри одного отчёта. |
| **Toolbar** | Общие фильтры: даты, продукты, пользователи… |
| **Карточка** | Одна диаграмма (или таблица) + свой заголовок. |
| **Чипы** | Показывают, что сейчас выбрано; часто можно снять кликом. |

Карточки обновляются после смены фильтра (обычно с небольшой задержкой — debounce). Не нужно жать «Применить», если на экране стоит авто-режим.

## 4. Фильтры

### Период (даты)

Чаще всего есть диапазон вроде «последние 30 дней».

- Меняешь **с / по** — все карточки, которые **слушают** этот фильтр, пересчитаются.
- Если на карточке «Нет данных за выбранный период» — сначала расширь даты или сними лишние измерения.

### Combobox / список значений

Поля вроде «Программа», «Локация», «Пользователь»:

1. Открой список.
2. Выбери одно или несколько значений (зависит от отчёта).
3. Дождись обновления карточек.

Значения в списке обычно берутся из базы (distinct по колонке). Пустой выбор = «не режем по этому полю».

### Что реально сужает карточку

Важно: фильтр на toolbar **не обязан** действовать на каждую карточку.

Автор явно пишет, какие фильтры карточка **слушает** (`bind`).

Пример поведения:

| Действие | Карточка Form (bind: дата + все измерения) | Карточка Projects (bind: только дата) |
|----------|--------------------------------------------|----------------------------------------|
| Выбрал пользователя | сузится | **не** сузится |
| Сменил период | сузится | сузится |

Если после клика по пользователю «проекты» показывают весь мир — это не «магия базы», а отсутствие привязки фильтра к карточке. Напиши автору отчёта.

## 5. Клики по диаграммам

На многих отчётах клик — это **действие**, а не просто подсветка.

### Что бывает при клике

| Тип | Что происходит |
|-----|----------------|
| **Поставить фильтр** | Клик по столбцу / сегменту donut / ячейке heatmap пишет значение в фильтр (например `location = /MOC`). |
| **Показать детали** | Под графиком появляется список / ключ-значение (удобно копировать). |
| **Перейти на вкладку** | Откроется Detail / другая вкладка с уже выбранными фильтрами. |

### Легенда donut / pie

Клик по пункту легенды (или по сегменту) в свежих Host **ставит фильтр категории**, а не «прячет кусок графика» как в обычном Chart.js.

Если ничего не меняется — либо у карточки нет `on click`, либо попал в «Прочие» (см. ниже).

### Heatmap

Клик по ячейке может сразу задать **два** фильтра (ось X и ось Y), например дату и пользователя.

### «Прочие» / Other

На bar/donut мелкие категории иногда сворачиваются в сегмент **«Прочие»** (или `Other`).

Это **не настоящее** значение в базе. Клик по нему **намеренно игнорируется** — иначе получишь пустые карточки.

Что делать: расширь период, сними другие фильтры или смотри топ без свёртки (если автор поднял лимит категорий).

### Смена измерения кликами подряд

На overview-дашбордах с несколькими «верхними» диаграммами (локация / проект / программа / пользователь):

- новый клик по другому измерению обычно **заменяет** предыдущий field-фильтр (дата остаётся);
- так меньше ситуаций «локация A **и** программа B» с почти пустым пересечением.

Если нужны оба измерения сразу — выбирай их в toolbar (если виджеты это позволяют), а не только кликами.

## 6. Пустые карточки и «странное» поведение

### «Нет данных за выбранный период»

Проверь по порядку:

1. **Период** — есть ли вообще события в эти дни?
2. **Чипы фильтров** — не накопилось ли несовместимое пересечение (локация × проект × пользователь)?
3. **Сброс** — сними field-фильтры, оставь только дату; снова кликни одно измерение.
4. Если пусто и без фильтров — данных в источнике нет, или отчёт смотрит не ту базу (это уже к администратору).

### «Человек работает на всех проектах»

Чаще всего карточка проектов **не слушает** фильтр пользователя: показывает всех за период.

В корректном отчёте после выбора пользователя проекты схлопываются до его реальных (обычно 1–3, не весь каталог).

### Числа «не сходятся» между карточками

Разные карточки могут считать разное:

- разные view / зерно (день × измерение vs день × час × …);
- разные `bind` (одна режет по пользователю, другая — нет);
- округление / Top-N / «Прочие».

Сравни сначала период и чипы, потом эскалируй автору.

## 7. Вкладки и фазы

Некоторые отчёты прячут детальные карточки, пока не выбран пользователь или продукт (`when` / phase browse→detail).

Типичный сценарий:

1. На Overview кликаешь ячейку heatmap.
2. Host ставит фильтры и переключает на вкладку Detail.
3. Там уже узкий срез.

Если Detail пустой — вернись, сними фильтр, выбери другую ячейку.

## 8. Экспорт и служебные страницы

Зависит от установленных плагинов и режима Host:

| Что | Зачем |
|-----|--------|
| Кнопка экспорта на карточке | Выгрузка (если включён plugin Export). |
| `/health` | Жива ли служба. |
| Dev Spec / resolve | Для авторов: разобранная спека, не для ежедневной работы аналитика. |

---

## 9. Краткая шпаргалка зрителя

1. Открой URL → при необходимости ключ на `/access`.
2. Выбери отчёт и вкладку.
3. Поставь период.
4. Кликай сегменты **по одному измерению**, смотри чипы.
5. Пусто → сбрось field-фильтры, не кликай «Прочие».
6. Подозрительно «все проекты у одного человека» → скорее bind, не база; напиши автору.
