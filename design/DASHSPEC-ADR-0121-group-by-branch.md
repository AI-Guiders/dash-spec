# DASHSPEC-ADR-0121: Группировка — ветка графа в отдельный порт карточки

## Context

Агрегация в DashSpec сегодня живёт во вьюхах СУБД — и это осознанно: мы не
уносим в рантайм то, что должна делать СУБД, иначе умрём в рантайме. Push-down
агрегации уже происходит, точка правды — репозиторий БД.

Но есть фича, которую вьюхи не закрывают: **группировка в таблицах**. Обсуждалась
не раз, не реализована никогда — именно потому, что по старой архитектуре она
требовала кучи ручного бойлерплейта в слое показа (каждый визуал группирует и
агрегирует сам). Диагноз старой архитектуры: агрегация делалась там, где ей не
место.

ADR-0120 дал носитель, который меняет экономику: трансформы с контрактом
локальности (`database`/`runtime`), param-порты, сворачивание database-узлов
пути в один запрос, мульти-портовые карточки (слоты `card.<id>.<slot>` — уже
в грамматике). Группировка перестаёт быть бойлерплейтом и становится записью
в словаре трансформов.

## Decision

**`group_by` — database-transform; группировка — не мутация пути, а ветка
графа в отдельный порт карточки:**

```text
events -> to_zone ------------------------------------> [raw]     card.activity
      \-> group_by { by = app_name, agg = count } ---> [grouped]  card.activity
```

### Правила

1. **Локальность `database`**: узел компилируется в `GROUP BY` запроса
   источника (вместе с остальными database-узлами пути — фильтры, reduce —
   один `SELECT … WHERE … GROUP BY … TOP`). Словарь локальностей расширяется
   этой записью через настоящий ADR, как и договаривались в 0120.
2. **Выходной тип ≠ входному** — первая трансформа с этим свойством:
   `rows EventRow -> rows (key, aggregate)`. Типизация портов (ADR-0079)
   заявляет выходной row type честно; «фильтр по сырой колонке после
   группировки» — compile-ошибка несоответствия типов, не пустая таблица.
3. **Ветка, а не мутация**: основной поток не трогается — raw-порт живёт
   своей жизнью, drill по сырым строкам работает в полную силу. Инверсия
   кликов (G⁻¹) невозможна только на grouped-ветке — локально и честно.
4. **`by` может быть param-портом**: интерактивная группировка — пользователь
   меняет колонку → перекомпилируется один запрос ветки, `[raw]` не замечает.
   Механика «параметр → compiled-запрос» из ADR-0120, только параметр едет в
   `GROUP BY`, а не в `WHERE`. Виджет-группировщик (список доступных колонок)
   — tap по входному потоку узла, не словарь таблицы.
5. **Параметры**: `by` (колонка или param), `agg = count|sum|max|min|avg`,
   `value` (колонка-аргумент агрегата; для `count` не нужна).
6. **Sugar не заводится без покупателя**: escape hatch-форма (явный узел)
   достаточна для первого среза; авторский синтаксис родится из живого кейса
   (урок ADR-0120 — узловая форма без покупателя осталась бумагой).

### Вьюхи

Вьюхи остаются инструментом агрегации там, где срез стабилен и принадлежит
владельцу данных. `group_by` — для срезов, которые выбирает автор отчёта или
пользователь в рантайме. Двух точек правды нет: вьюха материализует, `group_by`
считает в полёте; выбор между ними — по тому, кто владеет и как часто меняется.

## Alternatives considered

- **Не делать (YAGNI)**: агрегация уже push-down'ится вьюхами. Отклонено:
  есть заблокированная фича (группировка таблиц), не реализованная именно
  из-за цены бойлерплейта в слое показа — покупатель существует, просто боль
  никогда не стала кодом.
- **Группировка в слое показа (по-старому)**: ручная агрегация в каждом
  визуале. Отклонено: это и есть тот бойлерплейт, из-за которого фича не
  родилась.
- **SQL в отчётах, подход Metabase** (расширение SQL прямо в спеках, визуальный
  query builder): отклонено — неизвестный формат, магические подстановки,
  всё тыкается мышкой; спека перестаёт быть текстом-проекцией графа и теряет
  reviewability/git-историю как источник правды. Наша линия — декларативные
  узлы над типизированными потоками, SQL собирает компилятор.
- **Мутация пути (group_by внутри основного потока)**: отклонено — ломает
  drill/инверсию для всего пути и требует семантики «переключаемых режимов»
  на одном порте; ветка в отдельный порт решает то же без переключателей.

## Consequences

- `+` группировка таблиц перестаёт стоить бойлерплейт: рендер получает
  типизированные сгруппированные строки и остаётся тупым.
- `+` интерактивная группировка — param на узле, без новой механики.
- `+` цепочка `group_by -> reduce` сворачивается в один запрос: сырые строки
  не доезжают до памяти.
- `−` первая трансформа с изменением row type — типизация портов должна
  довестись до честного выходного типа (вход в реализацию).
- `−` grouped-ветка необратима для инверсии кликов — задокументировано,
  локализовано веткой.
