# DASHSPEC-ADR-0118: Контракт ролей фильтров — skin уходит стеку, реализации становятся замещаемыми

## Context

Закрывает Open #5 [ADR-0112] («граница filter-плагин vs стек») — кейс, доведённый до боли живым экраном: календарь фильтра «Период» остался в стоковой светлой шкуре на navy-теме; опции комбобокса были невидимы (чёрный текст кнопок на navy — кнопки не наследуют цвет, плагинный css не задавал цвет опций вовсе).

Сегодня (факты, [ADR-0060] работает как записано):

- **В спеке смешаны роль и тип виджета** (расщепление — оператор, 2026-11-03): `widget = combobox | chips | select | day | range` назван ролью, но это **типы** — и по критерию [ADR-0112] («намерение или выражение?») они неоднородны: `combobox | chips | select` — чистое **выражение** (как показать выбор — дело стека), `day | range` — полукровная **функция** (что юзер может выразить). Настоящая роль — функциональная: `selector` (выбор из набора), `date-input` (дата/период), `top-n` (лимит выборки). `widget =` — фильтровый аналог умершего per-diagram `render`: авторская подсказка реализации, место которой — маппинг стека. Словарь захардкожен в `FilterParser`, не реестр.
- **Реестр id → компонент уже федеративный**: `FilterWidgetRegistry` (surface) резолвит id из `contributors.FilterWidgetComponents`; плагины регистрируют (`RegisterFilterWidgetComponent(widgetId, type)`); `FilterWidgetHost` — тонкий `DynamicComponent`-слот. «Продуктовые виджеты во внешних DLL» — Next [ADR-0060].
- **Три разрыва против модели VisualTree** ([DASHSPEC-NOTE-visual-tree-role-contract]):
  1. роль — слово без **контракта функций** (что `date-input` обязан уметь — нигде не декларировано);
  2. реестр **глобальный, не per-stack**: оба стека получают одни компоненты, замещаемости нет;
  3. **шкура едет внутри компонента**: flatpickr css (стоковая светлая) грузится плагином — визуал ниже уровня VisualTree, нарушение [ADR-0112] «CSS задаётся тем, кто рендерит».

## Decision

Минимальная форма: контракт регистрируется рядом с компонентом, skin уходит стеку через каскад, per-stack биндинги — отложены до второго живого потребителя.

### 1. Роли получают контракт; типы умирают как авторская опция

Роль одна — **`selector`**: выбор значения(й) из набора кандидатов (оператор, 2026-11-03: «date-input — это тоже selector, только даты»; top-n рендерится тем же выбором числа). Роль параметризуется **доменом кандидатов** и функциями:

- домен кандидатов: `values` (строки из поля), `dates` (календарь), `numbers` (лимит выборки);
- функции на контракте: `single/multi`, `search`, `culture-parse` + `range-grammar` + `day/range`-режим (для домена дат — функциональная часть бывших типов живёт здесь), `limit` (числа).

`RegisterFilterWidgetComponent(role, domain, contract, type)` — регистрация реализации роли с доменом и контрактом; грамматика дефолтов остаётся в Core ([ADR-0060] line 19).

**Выражение роли — каскад трёх инстансов** (вместо смерти `widget =` одним махом; оператор, 2026-11-03):

1. **Стек** — дефолтное выражение роли своим языком;
2. **Автор** — намерение плотности, не компонент: `selector { density = inline | collapsed }` — «юзер видит варианты без открытия» vs «компактно». Автор говорит зачем; стек выражает inline своими средствами (у Radzen — чипы, у другого стека — иначе). Это намерение (что юзер может сделать), не выбор компонента — потому остаётся в спеке;
3. **Пользователь** — царь (оператор): персональное предпочтение выражения селекторов (чипы/комбобокс/…), перекрывает автора и дефолт стека — тот же механизм, что пер-юзер тема (кука + пикер); уже имеет прецедент — `LargeFieldFilterLayout` (scroll/expand) в настройках представления.

Переходно: `widget = combobox` читается как `density = collapsed`, `widget = chips` — как `density = inline`; миграция спек — замена строк на density (семантика сохраняется, компонентное слово уходит).

### 2. Skin — уровень стека (правило владения)

- Компонент виджета — **структура + поведение**, нейтральная разметка; красит каскад темы стека (`inherit`, переменные стека — потребление CSS семьи допустимо, оператор 2026-11-03).
- Календарь: flatpickr `.min.css` остаётся структурным (позиционирование/сетка); **цвета поверхностей и текста переезжают в темы стека** (`theme-dark.css` / `theme-light.css` Radzen-стека красят `.flatpickr-calendar`). SelfMade красит своими токенами.
- Эталон паттерна уже в коде: опции комбобокса (`color: inherit` + currentColor-подсветки) — коммит `6833505`.

### 3. Per-stack биндинги — отложены (не отклонены)

`IRenderStack` + опциональный `FilterWidgetBindings` (роль → своя реализация стека, фолбэк — глобальная регистрация) — форма записана, запуск **когда появится второй живой потребитель** (сегодня оба стека потребляют Filter.Builtins; RadzenDatePicker вместо flatpickr — первый кандидат, когда решится). Преждевременная развилка — churn ([ADR-0108]).

## Rejected

- **Посадить фильтры на компоненты стека** (RadzenDatePicker/ComboBox в виджетах) — рвёт «виджеты одни, стеки разные» ([ADR-0060]): семантика (культура, bind, топы) размазалась бы по чужим компонентам; домен доменом, визуал стековым (оператор, 2026-11-03).
- **Нейтральный токен-контракт для гостей** (`--ds-*` поверх `--rz-*`) — совпадает с Rejected «общая палитра-контракт» [ADR-0112]: гость семьи потребляет CSS хозяина; стек меняет CSS по необходимости (оператор, 2026-11-03).
- **Оставить flatpickr-шкуру в плагине с dark-вариантом** — плагин красит = нарушение границы; dark-вариант в плагине умножал бы шкуры вместо передачи владения.

## Приёмка

- Календарь «Периода» читаем в `dark` и `light` на Radzen-стеке; смена theme-токена меняет календарь без правок плагина.
- Неизвестное `widget =` слово — ошибка парсера с перечнем зарегистрированных ролей.
- Новый per-stack потребитель фильтров подключается биндингом без правок Filter.Builtins.
- Спеки: `widget = combobox|select` → `density = collapsed`; `widget = chips` → `density = inline` (даты `day/range` → функции роли `date-домена`) — грамматика хоста расширяется density, корпусы правятся один раз.

## Open

1. Состав слов контракта (`culture-parse`, …) — зафиксировать при первой реализации реестра контрактов; минимальный старт — `skin: cascade|own` на существующих шести виджетах.
2. Срок миграции `own`-шкурок — не назначается до боли (порядок [ADR-0108]).
