## Context

ADR-0074 (2026-10-01) определила: спека → композер → `ComposedDashboardView` → Host-проекция. Проверка кода (2026-10-21) показала (адреса — по факту):

1. **Имя «композер» занято парсером**: F# `DashboardComposer.parse` — merge таб-модулей + `DocumentCompilePipeline.completeDocument` (фаза `BuildWiringGraph` внутри). Слияние — легальная часть конвейера компиляции ([ADR-0097]); строка миграции ADR-0074 §6 «MergeReferencedTabModules → composer pipeline» отменена.
2. **Грамматик `navigation/section/initial` из 0073/0074 не существует** (grep по F# — ноль). Навигационная модель: catalog entry (`InitialTabId`) → `TabDefinition[]` → `ReportPageDefinition[]`.
3. **Геометрия считается в момент рендера, в хосте**: fallback-ряд тулбара и «первая вкладка/страница» в `DashboardPageController` (L1180, L1297–1321, `ResetActivePageForTab` L1420, дубль в `TabLayoutCompactor` L40–43), интерьеры — `DashboardLayoutHelper.ResolveInteriorPlacements` на рендере, скрытие nav по `Count > 1` (6 мест), видимость тулбар-фильтров пересечением с картами (`ToolbarFilterVisibility` — ровно то, что §4 ADR-0074 запрещает Host'у).

При этом **вся математика и весь словарь уже существуют и используются** (`Execution.Runtime`: `TabLayoutBoardResolver`/`TabLayoutCompactor`/`TabLayoutPlanner`/`ToolbarLayoutCompactor`/`LayoutSlotEngine`/`CardInterior*`/`LayoutBoardRowPlacer`/`FilterPlacementAnalyzer`; идентичность — `WiringNode.Id`, `CardFlowInput.NodeId`, имена слотов в грамматике). Не существует одного: **собранного дерева композиции** — вывод этой математики (`SlotEngine` и соседи) разлетается по вызовам на рендере, каждый вызов пересчитывает свой кусок геометрии под свой контекст, дерево нигде не собирается.

Оператор (2026-10-21, постановка рамки): отделить структуру от рендера — рендер только размещает по уже собранной модели; сборку структуры свести в SSOT. Паттерн — **Компоновщик (Composite)**, форма — **дерево компонентов, как визуальное дерево WPF**: типизированные узлы, адрес узла — его путь от корня, никаких scope-строк. Контейнер сегодня — грид, но по сути им может быть что угодно: форма узлов его не прибивает. Существующая грамматика уже является сериализацией этого дерева (`layout [ app_period ] [ products:3 users:9 ]` — строка-слоты-спаны; доска таба; тулбары и зоны оболочки [ADR-0110]; nest/group — вложенные гриды). SSOT не изобретает язык и словарь — существующее продолжает использоваться, просто теперь всё это **потребляет одно дерево**.

Юзкейс-эталон (вкладка «Обзор», дословно от оператора):

```
Composition («Обзор»)               ← корень: композиция вкладки
 └─ Grid
     ├─ Row (Toolbar)               ← строка хрома
     │   └─ Slot usage_date         ← слот фильтра (Id = имя — склейка с wiring)
     └─ Row (контент)
         ├─ Slot app_period (span)
         └─ Slot products (span 3)
             └─ Card app_users      ← предмет (Id — склейка с wiring)
                 └─ Grid            ← интерьер карточки — рекурсия,
                     └─ Row             как UserControl в WPF несёт своё дерево
                         └─ Slot (Diagram)
```

## Decision

### 1. Артефакт — `VisualTree`: типизированное дерево компонентов; модель — на F#

Прецедент словаря — `WiringGraph` (`DashSpec.Modeling.Core`, `WiringGraph.fs`): узел несёт `Id`, никаких ref-типов, склейка — тот же `Id`. Форма — НЕ плоский граф wiring'а (он про рёбра между сущностями, поэтому строки уместны), а **дерево** (как визуальное дерево WPF): адрес узла — путь от корня, тип узла — сам кейс DU. Типы — F#, в `DashSpec.Modeling.Core` (рядом с `WiringGraph.fs`):

```fsharp
// VisualTree.fs — дерево компонентов (WPF-подобное): типизированные узлы,
// адрес = путь от корня; scope-строк нет — «какая вкладка» = какое дерево.

type VisualNode =
    | VGrid of VisualGrid          // контейнер; сегодня единственный, форма не прибита
    | VRow of VisualRow            // строка доски `[ … ]`
    | VSlot of VisualSlot          // именованная ячейка: Id = имя слота ('products')
    | VCard of VisualCard          // предмет-контейнер: карточка + её интерьер
    | VDiagram of DiagramDefinition  // лист: объект диаграммы — тот же экземпляр из документа
    | VFilter of FilterDefinition     // лист: объект фильтра — тот же экземпляр из документа
    // … кейсы растут по живым инстансам ([ADR-0108]), не параллельными енумами

and VisualGrid =
    { Rows: VisualRow list }       // geometry грида — его свойства (колонки/зазоры)

and VisualRow =
    { Cells: VisualSlot list }     // строка несёт слоты

and VisualSlot =
    { Id: string                   // имя слота — тот же Id, что у WiringNode (склейка
                                    // двух SSOT без ref-типов)
      Span: int                     // спан из декларации (`products:3`)
      Provenance: PlacementProvenance
      Content: VisualContent }

and VisualContent =
    | Item of VisualNode            // предмет в ячейке: карточка/диаграмма/фильтр/…
    | Nested of VisualGrid           // вложенный контейнер (nest/group/зона)

and VisualCard =
    { Card: CardDefinition           // объект карточки — тот же экземпляр из документа
      Interior: VisualGrid option } // интерьер — поддерево (рекурсия Компоновщика)

type PlacementProvenance =
    | Declared            // автор объявил ячейку в спеке
    | RecordedDefault     // сборка подставила умолчание и ЗАПИСАЛА его ([ADR-0109])
```

- **Никаких scope-строк**: адрес узла — путь от корня; «какая вкладка» — какое дерево. Корни композиции: `Shell` (зоны оболочки, [ADR-0110]) и по дереву на вкладку (её доска: строка тулбара + строки контента). Артефакт — набор корней, ключ — Id вкладки (id, не scope-строка).
- **Тип узла = кейс DU**: никакого `Kind`-енума и строковых видов; новый визуальный элемент — новый кейс по живому инстансу.
- **Item — объект, не строка и не копия**: лист несёт само определение из собранного документа (`DiagramDefinition`, `FilterDefinition`, `CardDefinition`) — **тот же экземпляр** (записи неизменяемые, разделение экземпляром бесплатно); рендеру не нужно ничего искать по Id. Собственный `Id` объекта остаётся склейкой с wiring-графом ([ADR-0091]). Членство карточки в (tab, page) — позиция узла; отдельных списков членства нет.
- **Карточка — узел-контейнер**: несёт интерьер как поддерево — рекурсия Компоновщика, как `UserControl` в WPF несёт своё дерево.
- **Геометрия структурная**: индекс строки, позиция слота в строке, спан — финальные координаты выводятся обходом дерева (вывод = функция над деревом), а не хранятся в строках; `PlacementDefinition { Row; Col; Span }` — один тип на размещение, расширяется он, если понадобится.
- **Grid — единственный контейнер сегодня**, но union `Item | Nested` форму не прибивает: будущий stack/dock — ещё один кейс контейнера, спека и сборка не меняются.
- **NavBands** — тоже деревья: полоса (`portal|section|page`) — грид со слотами-листами на Id записей каталога/вкладок/страниц. `InitialRoute` — записанное умолчание артефакта (`RecordedDefault`).

### 2. Сборка — одна точка, один раз на ревизию; вся существующая математика потребляется как есть

`VisualTreeBuilder` — в `DashSpec.Execution.Runtime`, **рядом с математикой, которую он вызывает**: (`DashboardDocument` + `CatalogDocument`) → набор деревьев композиции (типы — F# из `Modeling.Core`). Существующие резолверы/компакторы/планировщики (`TabLayoutBoardResolver`, `TabLayoutCompactor`, `TabLayoutPlanner`, `ToolbarLayoutCompactor`, `LayoutSlotEngine`, `CardInterior*`, `LayoutBoardRowPlacer`, `FilterPlacementAnalyzer`) **остаются на своих местах — их вывод ложится в узлы деревьев**. Никакого порта: переписывание работающей математики без второго инстанса — churn ([ADR-0108]).

**Математика сборки — одна и рекурсивная**: грид интерьера карточки собирается тем же правилом, что доска вкладки, строка тулбара и зона оболочки — уровни отличаются только тем, **откуда декларации** (`layout`-блок карточки / доска вкладки / тулбар-доска / host-доска), а не тем, как они собираются. Поэтому фазы не режутся «по зрелости уровней»: билдер один и сразу рекурсивный; **единица миграции — потребитель рендера** (место вызова, пересчитывающее геометрию на рендере, переключается на чтение дерева), см. §4.

Точка сборки — **bootstrap загрузки отчёта** (`ReportSpecBootstrap`): один вызов на загрузку/ревизию документа, артефакт едет в bootstrap-результате рядом с документом и wiring-графом. Параллель имён: `DocumentWiringGraphBuilder` (данные) + `VisualTreeBuilder` (структура) — модель у обоих F# (`Modeling.Core`), билдер каждого живёт там, где считается его вывод.

Артефакт **маршруто-независим**: все корни сразу — оболочка, доска и тулбар каждой вкладки, интерьеры всех карточек, все полосы. Никакой «нарезки по маршруту»: смена вкладки в хосте — выбор дерева, не пересборка.

**Громкая семантика** ([ADR-0109]): два предмета в один слот — ошибка сборки; неизвестный `Id` — ошибка сборки; умолчания (family-defaults, fallback-ряды, first-tab/first-page) — записываются с `RecordedDefault`, а не применяются тихо.

### 3. Сессия — оверлей, не мутация

Fold (`fold = independent` уже в спеках), занятость, активная `(tab, page)`, выбор — состояние сессии в хосте, **наложенное** поверх иммутабельных деревьев при рендере. Деревья не мутируют от взаимодействия. Эта граница проведена жёстко: ранняя редакция с «композитором, нарезающим по маршруту», отменена — нарезка по активному маршруту и есть сессия (§4 ADR-0074: «активный выбор, busy — это сессия, а не композер»).

### 4. Рендер — тупой обход: существующий код потребляет дерево

Рендерный путь меняет вход, не устройство: `VGrid` → контейнер раскладки (`PlacementGridCss` из вычислителя становится проектором), `VRow` → строка, `VSlot` → ячейка, `Item` → отрисовать объект (лист несёт определение — искать ничего не нужно), `VCard` → карточка + рекурсия в интерьер. В контроллере умирают `RecomputeToolbarPlacements`, per-render `ResolveInteriorPlacements`, гейты `Count > 1`, label-эвристики — чтение дерева + сессионный оверлей:

| Эвристика сегодня | Становится |
|-------------------|------------|
| «Первая вкладка» (`DashboardPageController` L1180) | `InitialRoute.TabId` — записанное умолчание |
| «Первая страница» (`ResetActivePageForTab` L1420, дубль `TabLayoutCompactor` L40–43) | `InitialRoute.PageId` — записанное умолчание |
| Скрытие nav при `Count > 1` (6 мест) | Рисуется объявленное; умолчание — записано |
| Label-эвристика `Tabs.Count > 1` (`DisplayResolution.ResolveTabLabel`) | Label в узле, Host читает готовое |
| `ToolbarFilterVisibility` (пересечение с картами) | Спек-объявленные слоты + флаг `Bound`; рендер рисует disabled, не прячет (§4 ADR-0074) |
| Fallback-ряд тулбара (L1297–1321) | Умолчание, записанное в дерево при сборке |
| `TabLayoutPlanner`/`LayoutSlotEngine` на рендере | Потребляются сборкой; их вывод — в дереве, Host читает |

### 5. Языковая добавка (минимальная, по духу ADR-0109)

Catalog entry получает `page <pageId>` симметрично `tab <tabId>`: `InitialPageId: string option`. Сборка валидирует громко (неизвестная страница/вкладка — ошибка, ссылка на entry). Fallback каталога «первая запись» — заменяется записанным умолчанием.

### 6. Приёмка фундамента — визуальная

Фундамент принимается не сам по себе, а домом: conformance-цели — экраны образца («взрослый BI», HTML-образец Сергея). Дерево считается готовым по корню, когда тупая проекция этого корня даёт задуманный вид. Фундамент не уезжает в абстракцию, потому что его проверяют глаза.

## Rejected

| Идея | Почему |
|------|--------|
| `VisualModel` + `VisualCompositor` как сущности (`be18e71`/`4e490a4`) | Композитор выжил бы с чужой работой: «нарезка по маршруту» — сессия, а не слой; артефакт несёт все корни сразу, хост выбирает дерево |
| C#-контракт типов (правка этого же дня) | Модель дома — на F# (`Modeling.Core`, прецедент `WiringGraph.fs`) |
| F#-фаза конвейера с портом математики (правка этого же дня) | Вся существующая математика продолжает использоваться — билдер потребляет её вывод; порт без второго инстанса — churn ([ADR-0108]) |
| `ItemRef`/`VisualItemKind` — отдельные ref-типы (правка этого же дня) | Узел листа — сам узел: `Id` по конвенции `WiringNode`; склейка — тот же Id; второй словарь = параллельная истина |
| **Плоский граф со scope-строками (`Scope: string option` «tab:{id}»…)** (правка этого же дня) | String obsession: конвенция wiring-графа (плоские рёбра) перетащена туда, где адрес — путь от корня, а тип — кейс DU. WPF-дерево: адрес структурный, «какая вкладка» = какое дерево |
| **Листья `of string`** (правка этого же дня) | Диаграмма и фильтр — полноценные объекты модели (`DiagramDefinition`/`FilterDefinition`): лист несёт объект — тот же экземпляр из собранного документа (неизменяемые записи — разделение экземпляром бесплатно); рендеру не нужны поиски по Id |
| Новый проект для P0 | Типы — `Modeling.Core`, билдер — `Execution.Runtime`; отдельный проект — по реальной нужде |
| Перенос merge таб-модулей в рантайм | Merge — конвейер компиляции ([ADR-0097]); дублировать — второй движок |
| Универсальное DOM-подобное дерево без живых кейсов | Сущность без второго инстанса ([ADR-0108]); кейсы растут от живых поверхностей |
| Скрывать тулбар-фильтры эвристикой пересечения | Нарушает §4 ADR-0074; честный путь — слоты + `Bound` + disabled-состояние |

## Consequences

- Одна структура UI = один источник для Blazor, плагинов, Studio и headless-экспорта; воспроизводимость из артефакта.
- Существующее продолжает использоваться: математика — на своих местах (потребляется сборкой), словарь Id — один; новый тип — только типизированное дерево Компоновщика (WPF-форма) + флаг provenance.
- `DashboardPageController` худеет до обхода + сессии; Surface перестаёт быть «вторым автором».
- Визуальная итерация — правка декларации + дамп дерева: собрал, посмотрел композицию целиком.
- Два SSOT — данные (wiring-граф, [ADR-0091]) и структура (VisualTree) — склеены по Id; никакого дублирования истины.
- [ADR-0110] обновлена на термин `VisualTree`.
