# DASHSPEC-ADR-0128: Authored surface для выведенных типов

## Context

ADR-0127 дал инференс row types: синтезированные типы (`ModelByReleasedRow`,
join-merge `ModelJoinOrgRow`) живут только в IR — `DashflowModule.InferredRowTypes`
и manifest managed views. Автор не видит их как типы языка: чтобы носить
человеческое имя (вместо безликих коллизионных суффиксов), он вынужден
транскрибировать поля руками.

При этом в доме уже есть всё для обратного направления:

- **AST** (`DashSpec.Modeling.Parse.Syntax`) — Roslyn-style typed tree,
  токены несут текст (`SyntaxToken.Text`), блоки/линии — surface-гранулярность;
- **`DashSpecConceptGraph` + `DashSpecSerializeRules`** (CodeCenter) — граф
  концептов из AST и сериализационные правила с round-trip законом
  (parse → graph → serialize → parse даёт эквивалентный outline);
- **правило предпочтения двойника** (ADR-0127): рукописный structural twin
  каталога предпочитается синтезу; mismatch — compile error.

Чего нет: проекции **AST → text** (оба сериализатора сегодня text → text:
`serializePreserve` возвращает исходник, `serializeFormat` гоняет
`DashSpecBlockFormatter` по тексту) и синтеза **IR → AST** для types-юнитов.

## Decision

### 1. Сгенерированный тип — не статус, а история

Система типов **не различает** generated/authoring. Компилятор предпочитает
авторский тип по структурному равенству — этого достаточно. Эмит создаёт
types-юнит; после первой эмиссии файл **авторский**: переименования, порядок
блоков, комментарии — принадлежат автору. В языке не появляется ни маркера
`type X: Generated`, ни provenance-якорей.

### 2. Эмит = AST-поддерево, а не текст

Компилятор не работает с текстом. Пайплайн:

```
RowTypeDef (IR)  →  синтез AST-узлов types-юнита  →  AstPrinter  →  текст
```

- **`DashSpecAstPrinter`** (Modeling.Parse / CodeCenter — размещение по итогам
  реализации): поддерево → текст. Однозначно по построению: токены несут текст;
  canonical layout — существующий `DashSpecBlockFormatter`. Инвариант —
  round-trip закон (распечатанное дерево обязано репарситься в эквивалентный
  outline; иначе это баг принтера).
- **Синтезатор `RowTypeDef → AST`**: types-юнит с блоками `type <Name> … end type`,
  поля с опциональностью и типами из `RowFieldDef`. Квалифицированные имена
  (`r.name`) — валидные идентификаторы поверхности, отдельной обработки не требуют.

### 3. Регенерация — матчинг в три шага, точечный CRUD членов

Наивный «двойник по структурному равенству» не работает для CRUD членов:
если структура совпала 1-в-1, дельта полей по определению пуста — нечего
патчить; а как только состав полей во flow изменился, переименованный
автором тип перестаёт быть структурно идентичным кандидату — матчинг падает
в «двойника нет» и плодит дубликат рядом с авторским блоком. Поэтому
сопоставление кандидата из IR с блоками существующего файла идёт в три
шага, все — из .ds-графа, без каких-либо маркеров:

| Шаг | Критерий | Действие |
|---|---|---|
| 1. Графовая привязка | порт цепочки (`output rows: DomainStatRow`) или карточка, читающая этот узел flow, уже ссылается на тип — связка «узел ↔ блок» известна из AST | точечный CRUD членов блока на месте: поля добавляются/удаляются, авторское имя и комментарии сохраняются |
| 2. Структурный двойник | структура кандидата совпала 1-в-1 с существующим блоком — автор переименовал тип, поля ещё не менялись | авторский блок переиспользуется (дельта полей = 0, дубликат не рождается) |
| 3. Выведенное имя | автор тип не переименовывал, но поменял поля во flow | блок `type ModelByDomainRow` находится по имени и патчится на членах |

Ни один шаг не совпал — новый блок добавляется под выведенным именем.
Блок, который больше ни от чего не зависит и не матчится ни одним шагом,
остаётся как есть (авторская собственность); если он ещё аннотирован
портом — штатная compile-диагностика mismatch.

Никакого auto-overwrite: файл после эмиссии правится только merge-дельтой.
Циклов нет: emitted-файл участвует в compile как обычный types-юнит через
импорты — компилятор потребляет его как IR, как и любой другой юнит.

### 4. Имена без коллизионной арифметики

`baseNameForEffect` для Projection учитывает by-колонку
(`Model + domain → ModelByDomainRow`) — суффиксы `2/3` остаются последним
рубежом, а не нормой именования (реализовано в ADR-0127-ветке ранее этого ADR).

## Consequences

+ Автор работает с выведенными типами как с обычными: переименовал —
  компилятор подхватил (twin-правило), поля транскрибировать не нужно.
+ Язык не обрастает generated-механикой: якоря, маркеры, special-casing — нет.
+ Round-trip закон даёт бесплатный валидатор принтера.
− AstPrinter — новая поверхность: любая новая синтаксическая конструкция
  обязана печататься (стоимость растёт с языком); до реализации принтера
  допустимо печатать по токенам только types-юнитов.
− Rename + shape-change одновременно даёт дублирующий блок — автор
  разрешает вручную; генератор не угадывает.

## Plan

1. `DashSpecAstPrinter` — поддерево → текст (types-юниты first), round-trip тесты.
2. Синтезатор `RowTypeDef → AST` + точка входа (CLI: `dsc generate types <dir>`)
   с structural merge против существующего файла.
3. AI-корпус: эмит выведенных типов, авторские имена (`DomainSummaryRow` и т.п.),
   аннотация портов — демонстрация authored surface end-to-end.
