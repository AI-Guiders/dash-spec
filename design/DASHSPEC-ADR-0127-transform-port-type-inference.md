# DASHSPEC-ADR-0127: Transform port type inference — компилятор выводит типы портов трансформеров

## Context

Сегодня каждый `transformer` в `module flow` обязан вручную объявлять блок `ports` с явными типами входа и выхода:

```ds
source daily_peak_raw {
  from view v_daily_peak_concurrent_heatmap
  ports
    output stream raw: CalendarDayHeatmapRow
  end ports
}

transformer daily_peak_tz {
  ports
    input stream raw: CalendarDayHeatmapRow
    output stream rows: CalendarDayHeatmapRow
  end ports
  transform use to_zone { zone = UTC+3 }
}

daily_peak_raw [raw] -> [raw] daily_peak_tz
```

Пока трансформ в цепочке был один (`to_zone` с `T_out = T_in`), дублирование имени типа трижды было терпимым шумом. Но с переходом к `ADR-0125` (managed views) и `ADR-0126` (полное покрытие реляционной алгебры в `Std.Transformations.Database`: `summarize`, `order`, `window`, `join`, `union`) цепочка внутри `module flow` становится многошаговым конвейером:

```
source -> join -> summarize -> window -> to_zone
```

Если на каждом промежуточном шаге требовать от автора (человека или агента) вручную объявлять отдельный `type Step1Row`, `type Step2Row`, `type Step3Row` в `module types` и прописывать `ports` у каждого узла:
1. Автор вынужден руками пересчитывать схему промежуточных проекций, которую компилятор **уже знает детерминированно** из входного типа и параметров трансформации.
2. Любое добавление колонки в `summarize` или `window` требует синхронной правки 2–3 промежуточных объявлений `type`.

Ровно эту проблему для дуг карточек решил `ADR-0122` («автор пишет руками то, что компилятор выводит из уже декларированного за один шаг»), а `ADR-0124` (`dsc build types`) уже компилирует `RowTypeDef` из модели в CLR-классы `TypedRows.dll`.

## Decision

**Язык `.ds` остаётся строго и статически типизированным: источники (`source`) явно декларируют входной `row-type`, а типы портов и промежуточные `RowTypeDef` для стандартных трансформеров выводятся компилятором по правилам реляционной алгебры и материализуются в ту же модель типов (`ADR-0124`).**

### 1. Граница явной типизации vs вывода типов (Hindley–Milner / F#-принцип)

- **`source` (внешняя граница с БД) — всегда явно типизирован:**
  Узел `source` обязан указывать тип строки (`output stream raw: SessionRow`), поскольку это точка входа схемы в граф.
- **`transformer` — типы портов выводятся из входящих рёбер и type-effect'а трансформа из контракта словаря:**
  Если у `transformer` опущен блок `ports` (или опущены типы потоков в `ports`), компилятор проходит по топологически отсортированному ДАГу потока от `source`-узлов и вычисляет `T_in` и `T_out` каждого шага по **декларированному type-effect'у** трансформа (см. §1.1).

### 1.1. Алгебра type-effect'ов в контракте словаря (`Std.Transformations`)

После ADR-0126 slice 0.5 словарь трансформов — это декларации stdlib. Тип-эффект становится **полем контракта** рядом с `Locality`:

```
transform to_zone     type-effect: identity
transform order       type-effect: identity
transform sort        type-effect: identity
transform summarize   type-effect: projection { keep = by,  add = agg(fn, value) }
transform window      type-effect: extend     { add = as := fn(value) }
transform join        type-effect: compose    { left, right, optional = kind }
transform union       type-effect: require-equal
```

Компилятор реализует только **пять комбинаторов** и прогоняет их по рёбрам:

| Type-effect | Сигнатура | Правило |
|---|---|---|
| `identity` | `T -> T` | Схема не меняется; повторно используется тот же `RowTypeDef`. Имя типа не порождается. |
| `projection` | `T -> T'` | Поля `keep` переносятся со своими типами из `T`; поля `add` получают вычисленный тип (`agg(fn, value)`: `count` → `int`, `sum/avg/min/max` → тип `value`). |
| `extend` | `T -> T ∪ col` | Все поля `T` сохраняются, добавляется поле `add` (`rank/row_number/running_count` → `int`, `running_sum/running_avg` → тип `value`). Коллизия имён с `T` — ошибка компиляции. |
| `compose` | `T_left, T_right -> T'` | `T'` собирается из полей обоих входов (для `left` правые поля `optional`, для `right` — левые, для `full` — обе стороны). Одноимённые неключевые поля без алиаса/проекции — громкая ошибка. |
| `require-equal` | `T, T -> T` | Требует структурного совпадения входов; `T_out = T_left`. |

**Границы открытости.** Словарь трансформов расширяется внешне (stdlib-юниты, плагины), но алгебра эффектов **закрыта**: новый трансформ обязан декларировать один из пяти комбинаторов (реляционная алгебра замкнута — эти пять покрывают всё выразимое над строками). Если поведение не выражается комбинатором — контракт декларирует `opaque`: вывод типов для этого узла отключается, трансформ требует явного `output stream rows: MyType`, и цепочка после него типизируется дальше от этой явной точки. Добавление шестого комбинатора — отдельное ADR, не «походя».

**Ответственность автора словаря:** декларированный type-effect обязан соответствовать фактическому поведению трансформа (рантайм-батч ↔ выведенный `RowTypeDef`); проверяется контрактным тестом stdlib.

### 2. Синтез `RowTypeDef` для `dsc build types` (`ADR-0124`): человекочитаемые детерминированные имена

- Выведенный тип не является «динамическим» или «анонимным в рантайме»: на фазе компиляции графа (после typecheck) компилятор регистрирует для каждого нового структурного типа детерминированный `RowTypeDef` в каталоге.
- **Имена генерируются человекочитаемыми, неотличимыми от рукописных** — из материала type-effect'а:

| Type-effect узла | Имя |
|---|---|
| `identity` | **не порождается** — шаг сквозной, используется тип входа |
| `projection` (summarize) | `<База>SummaryRow`, при уточнении ключей — `PeakByAppNameUsageDateRow` |
| `extend` (window) | `<База>RankedRow` / `<База>№ColRow` |
| `compose` (join) | `AJoinedBRow` |

- **Предпочтение рукописного типа:** если в `module types` уже существует тип, структурно совпадающий с `T_inferred`, компилятор привязывается к нему и новое имя не генерирует.
- **Коллизии** разрешаются позиционным суффиксом (`PeakSummaryRow`, `PeakSummary2Row`), хэш — последний резерв.
- **Стабильность:** имя детерминировано от неизменного графа. Изменение графа (вставка/удаление шага, смена параметров `by`/`as`) порождает новые имена; старые классы из `TypedRows.dll` исчезают — это норма, миграция выведенных имён не предусмотрена. Контракт первого класса — только явная аннотация `output stream rows: MyType` (§3); выведенные имена предсказуемы, но источником истины остаётся компилятор.
- `dsc build types` (`ADR-0124`) компилирует эти синтезированные `RowTypeDef` в `TypedRows.dll` точно так же, как и ручные `type`-блоки. Для рантайма и Blazor-рендера разницы между ручным и выведенным типом не существует.

### 3. Явный `output stream rows: MyType` как верифицируемый контракт

- Если автор явно указал тип порта на трансформере (`output stream rows: MySummaryRow`), вывод типов **не отключается**, а работает как **строгий структурный верификатор**: компилятор выводит фактический тип `T_inferred` по формуле трансформа и проверяет, что `T_inferred` структурно совпадает с `MySummaryRow`.
- При расхождении (например, в `summarize` забыли колонку, которая объявлена в `MySummaryRow`, или перепутали тип агрегата) компилятор выдаёт точную ошибку на этапе парсинга/typecheck, а при совпадении привязывает порт к именованному `MySummaryRow`.

### 4. Дефолтные имена портов при опущенном `ports`

- Для унарного трансформера (`to_zone`, `summarize`, `order`, `sort`, `reduce`, `window`) при опущенном блоке `ports` действуют стандартные дефолтные порты: `default input raw`, `default output rows`.
- Для бинарных трансформеров (`join`, `union`) действуют стандартные входные порты `left` и `right` и выходной порт `rows`.

## Consequences

- `+` **Чистота DSL при отказе от SQL-редактора:** цепочка `source -> join -> summarize -> window -> to_zone` пишется без единого промежуточного `type StepNRow` и без дублирования `ports`, сохраняя 100% статическую типизацию и проверку имён колонок на этапе компиляции.
- `+` **Усиление проверки (`edge-typecheck` + `transform-typecheck`):** раньше компилятор верил на слово тому, что автор написал в `output stream rows: SomeType` у трансформера; теперь компилятор знает алгебру самого шага и ловит несоответствие между параметрами трансформа (`by`, `value`, `as`) и выходным типом.
- `+` **Полная обратная совместимость:** существующие спеки с явными `ports` продолжают работать и получают дополнительную проверку соответствия `T_inferred == T_declared`.
- `+` **Словарь самодокументируется:** type-effect живёт в декларации трансформа рядом с `Locality` (ADR-0126); компилятор знает только 5 комбинаторов + `opaque`, новые трансформы stdlib не требуют правок inference-кода.
- `+` **Эргономика для агентов:** имена выведенных типов предсказуемы (`PeakSummaryRow`), агент может ссылаться на них в `rows_type` карточки, не открывая `module types`.
- `−` В компиляторе графа (`DashSpec.Modeling.Parse` / `Core`) появляется фаза вывода типов перед генерацией `TypedRows.dll`; контракт stdlib обременяется полем type-effect (проверяется тестом соответствия эффект ↔ фактический батч).
