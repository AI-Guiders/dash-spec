# DASHSPEC-ADR-0124: Row types становятся CLR-типами через dsc build types (Roslyn CSharpCompilation)

## Context

Спека декларирует типы строк (`type LufEventRow { … }`), но компилятор DashSpec
хранит их как данные (`RowTypeDef` в каталоге) — CLR-типа не существует. По дороге
к рендеру доменный объект теряется: reader материализует плоские `DashValue[]`,
и рендер получает безымянный массив. Wire-контракт ADR-0087 (значение + схема
рядом) это узаконивал — ценой того, что нативные механизмы гридов
(LINQ-выражения по свойствам `TItem`: группировка, сортировка, фильтры) не
работают: у массива нет членов.

Группировка таблиц (ADR-0123) упёрлась в это же: Radzen `AllowGrouping` требует
POCO, и нам пришлось собирать группы руками. Вариант «порождать CLR-типы в
рантайме» (Emit) отвергнут — рефлексия/генерация на горячем пути. Компиляция
типов — шаг публикации корпуса (Roslyn `CSharpCompilation` внутри dsc), не
рантайм и не передеплой хоста: хост грузит готовую сборку рядом с каталогом.

## Decision

**Row types из спек компилируются в CLR-типы командой `dsc build types`
(Roslyn `CSharpCompilation`); хост грузит готовую сборку рядом с каталогом
без передеплоя; рендер получает честный `TItem`.**

1. **`dsc build types`** (и кнопка публикации в dashspec-studio зовёт её):
   dsc парсит types-юниты `.ds` (F#-модель — SSOT как всегда), генерирует
   C# — `sealed class` с типизированными свойствами (`date` → `DateOnly?`,
   `string` → `string?`, `int` → `int?`, `decimal` → `decimal?`,
   `datetime` → `DateTime?`, …), конструктор из `DashValue[]` (значения
   через `ToClr()` + unbox) и реестр `RowTypeRegistry` (`имя → typeof(T)`,
   `имя → фабрика(DashValue[]) → object`) — и компилирует Roslyn'ом
   (`CSharpCompilation`, Microsoft.CodeAnalysis.CSharp) в `TypedRows.dll`,
   которую кладёт рядом с каталогом корпуса.

2. **Никаких csproj у автора.** Автор работает только с .ds (+вьюхи в БД);
   публикация корпуса = .ds (+ пересобранная TypedRows.dll, если менялись
   типы строк). Source Generators не используются — компиляция живёт внутри
   dsc (это .NET-инструмент Execution-слоя; моделирование остаётся F#).

3. **Хост не передеплоивается**: при загрузке/обновлении каталога он находит
   `TypedRows.dll` рядом, грузит рантаймом (AssemblyLoadContext, unload при
   обновлении) и связывает с каталогом по имени.

4. **Материализация в конвейере**: `BuildTable` (конвейер, не рендер) строит
   CLR-строки через реестр по `RowsType` — payload несёт типизированные строки
   (реальный `TItem[]`) + `Type` для generic-инстанцирования. Рендер тупой:
   `MakeGenericType(payload.RowType)` + `DynamicComponent`, ноль резолва типов
   и ноль фабрик на стороне рендера. Тип не найден → громкая ошибка:
   сборка типов — шаг пайплайна публикации, отдельного wire-пути нет.
   `DashValue[]` остаётся внутренним проводом конвейера (runtime-трансформеры
   to_zone/grouping, фильтры) — за payload-границей таблицы его нет.

## Alternatives considered

- **Runtime-генерация типов (Emit)** — запрещена линией проекта; компиляция
  на публикации даёт то же без рантайм-механики. Отвергнуто.
- **Source Generators (csproj-обвязка корпуса)** — требуют csproj у автора
  и пересборки при публикации; автор работает только с ds, а хост не
  передеплоивается. Отвергнуто; Roslyn внутри dsc покрывает то же.
- **Остаться на wire-массивах навсегда** — каждый нативный механизм гриды
  приходится reimplement'ить руками (группировка уже, сортировка/фильтры
  следующие). Отвергнуто как накопление ручного дубля.
- **Dictionary<string, object> строки** — не члены типа, LINQ-выражения
  не работают. Не вариант.

## Consequences

- `+` доменный объект по всей дороге: спека → CLR → рендер; имена и типы
  полей живут в одном месте (types-юнит спеки).
- `+` нативные группировка/сортировка/фильтры гридов работают без ручных
  реализаций.
- `+` ноль рефлексии на горячем пути: генерация — на компиляции; рантайм —
  один lookup по имени при связке.
- `+` один путь рендера: рендер только отображает то, что дал конвейер
  (как `to_zone`), резолва типов в нём нет.
- `−` смена типов строк требует `dsc build types` (публикация); правки
  остальных частей спеки живут на лету, как сейчас.
