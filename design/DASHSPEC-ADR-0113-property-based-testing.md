# DASHSPEC-ADR-0113: Property-based testing — парсеры и грамматики как исполняемые законы

| | |
|---|---|
| **Status** | Proposed |
| **Date** | 2026-10-24 |
| **Tags** | #dashspec #testing #pbt #fscheck #parsers |

## Context

Ядро DashSpec — семейство F#-парсеров (`DashSpec.Modeling.Parse`: `BlockGrammar`, `BlockSyntax`, `AccessorGrammar`, Alias/Card-парсеры) плюс нормализации и рендеры. Тесты сегодня — фиксированные примеры (`[<Fact>]`); round-trip-проверки уже начаты руками (`Round_trip_preserves_legacy_diagnostic_fields` в Modeling.Core.Tests), но каждый кейс придуман человеком.

Для парсеров это самая дорогая форма тестирования: примеры покрывают грамматику точечно, а её края (пустые ячейки, пробелы, спецсимволы, вложенность) не воображаешь по одному.

Прецедент в федерации: миграция `guiders-fsharp/Ide.Session` на FsCheck 3.6.0 поймала реальный баг (UTF8-коллизию суррогатов в ключах артефактов) первым прогоном — юниты с фиксированными примерами её не видели в принципе.

## Decision

1. Принять PBT как форму конформанса для **чистых** кусков DashSpec: парсеры, рендеры, нормализации, десугар. Инфраструктура — FsCheck 3.6.0 (`FsCheck.FSharp`), CPM-пин в корне.
2. Канонические свойства парсеров (в порядке внедрения):
   - **Totality**: `∀ input: Document.IsSome ∨ Diagnostics ≠ []` — парсер не бросает;
   - **Round-trip**: `parse(render doc) = doc` на сгенерированных документах; `render(parse text)` идемпотентна;
   - **Whitespace-инвариантность**: пробелы вокруг ячеек не меняют семантический результат;
   - **Десугар ≡ блочная форма**: таблица и её десугаренная запись дают одну семантику (метаморфный оракул двух представлений — семья уже живёт этим правилом).
3. **Не мигрирует:** E2E, интеграции с рендер-стеком, golden-файлы, execution-тесты с IO.
4. Юнит-примеры удаляются только когда свойство покрывает их; регрессии фиксированных багов остаются примерами.
5. Дисциплина генераторов и именования (аксиома в имени свойства) — как в GUIDERS-FSHARP-ADR-0010; здесь свой репо-пин и свой список свойств, механика общая.

## Карта старта

| Проект | Свойства |
|---|---|
| DashSpec.Modeling.Parse.Tests | totality + round-trip грамматик блоков/аксессоров |
| DashSpec.Modeling.Core.Tests | round-trip диагностик (начато руками — достроить генератором) |
| DashSpec.Modeling.Language.Adapters.DashSpec.Tests | адаптер: диагностика не бросает, номера строк согласованы |

## Consequences

- Генератор валидного DashSpec-документа — инвестиция один раз, питает все свойства парсеров.
- Грамматика, у которой свойства зелёные на тысячах случайных документов, защищена лучше, чем сотней придуманных примеров.
- Цена: генераторы надо читать и поддерживать при смене грамматики.
