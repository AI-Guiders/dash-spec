# DASHSPEC-ADR-0122: Default flow wiring — компилятор синтезирует линейные дуги карточек

## Context

Сегодня карточка обязана объявлять проводку данных явно (`CardParser`:
«Card requires data flow wiring, report/page data flow, or use
\<card-preset\>»). На живом корпусе LUS это выглядит так: четыре карточки в
overview — четыре `data flow`-блока, и все четыре — одна и та же линейная
дуга `src [rows] -> [rows] <slot>`.

Автор (человек или агент) пишет руками то, что компилятор выводит из уже
декларированного за один шаг: источник известен (скоуп потока), слот известен
(`view`/`diagram ref`), типы строки известны (каталог типов, ADR-0098).

ADR-0120 решил ровно эту болезнь для фильтров: авторский синтаксис остался
декларативным, а рёбра графа (`producer -> filter* -> reduce -> anchor`)
синтезирует компилятор. Здесь — та же механика, ещё проще: нет каскадов,
нет доменов, нет reduce-инстансов.

## Decision

**Линейная проводка карточки синтезируется компилятором; `data flow` — сахар
для нелинейных случаев.**

- **SSOT не меняется.** Граф потока остаётся единственной моделью в IR.
  Синтез — фаза компиляции (как `FilterFlowSynthesis`): дефолтная дуга
  материализуется в тот же граф, отдельной «неявной» модели не возникает.

- **Правило синтеза однозначное.** Дуга `[rows] -> [rows] card.<id>.<slot>`
  синтезируется, когда одновременно:
  - карточка не объявляет свой `data flow` и не наследует карточный пресет;
  - в скоупе потока ровно один источник (report flow или подключённый
    `use flow`);
  - у карточки ровно один diagram-слот без payload-строк;
  - тип строки источника совместим со входом слота.

- **Неоднозначность — loud, не угадывание.** Два источника, два слота,
  switch-слот с payload, несовпадение типов — парс-ошибка «declare data
  flow», с перечислением того, что именно неоднозначно. Компилятор не
  подбирает источник по колонкам и не ранжирует кандидатов.

- **Явный flow всегда сильнее.** Заявленный `data flow` полностью отключает
  синтез для этой карточки (никаких «дефолт плюс довесок»).

- **Границы.** Ветвления остаются явными по определению: group_by-ветки
  (ADR-0121, `[raw]`/`[grouped]`), мульти-портовые слоты, drill-цели,
  карточки с несколькими источниками.

## Alternatives

- **Оставить как есть.** Цена — постоянный бойлерплейт на каждый линейный
  случай; для агентов синтаксис рёбер — лишний класс ошибок (порядок портов,
  алиасы, квалификаторы).
- **Умный подбор источника** (по совпадению колонок, по именам). Отвергнуто:
  это магия в духе Metabase (ADR-0121), тихие совпадения хуже loud-ошибки.
- **Пресеты проводки** (`use wiring <preset>`). Меньше покрытия, ещё одна
  сущность; правило синтеза проще и покрывает тот же массовый случай.

## Consequences

- Линейная карточка становится `card / diagram ref / view` — без блока
  flow; порог входа для агентов падает (не нужно знать синтаксис рёбер для
  80% карточек).
- Миграция не нужна: существующие явные `data flow` продолжают работать
  без изменений (синтез их не трогает).
- Линт (в духе ADR-0098 «Redundant Import»): явный `data flow`, совпадающий
  с синтезируемым, помечается как избыточный — компилятор знает, что он
  был бы выведен.
- Диагностика неоднозначности должна называть всех кандидатов (источники,
  слоты) — это не подсказка к угадыванию, а материал для явного объявления.
