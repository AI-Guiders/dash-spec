# Статусы ADR: жизненный цикл (dash-spec)

ADR — OKF-документы: статус живёт в **YAML-фронматтере**, тело документа его не несёт. (Происхождение схемы статусов — [Cascade IDE status-lifecycle](https://github.com/AI-Guiders/cascade-ide/blob/main/docs/adr/status-lifecycle.md).)

## Где живёт статус (OKF)

**SSOT — поле `status:` во фронматтере**, всегда в кавычках, одной строкой:

```yaml
status: "Accepted"
status: "Accepted (частично: P0–P2; P3 pending)"
```

Телесная строка `**Status:**` упразднена — её больше нет ни в одном ADR, синхронизировать нечего.

## Формат значения

`"<lifecycle-тег>[ (<квалификатор внедрения>)]"`

- **Первый токен до скобки — обязательно один из:**

| Значение | Смысл |
|----------|--------|
| **Proposed** | Черновик на обсуждение. |
| **Accepted** | Норма для кода и ревью. |
| **Superseded** | Заменено другим ADR. |
| **Deprecated** | Не использовать для новых изменений. |

- **Квалификатор** — опциональное уточнение внедрения в скобках: `частично`, `pilot`, `phased`, `direction`, `v1 …`. Plain text: без markdown (`**`), без кавычек-в-кавычках, скобки парные.
- Статусы-артефакты конвертации (`Unknown`, `Working document`) запрещены. Живой рабочий документ — не ADR: ему место в `DASHSPEC-NOTE-*`, решение из него выносится отдельным ADR.
- Два решения в одном файле («pilot принят, носитель Proposed») — текстом квалификатора; если решений действительно два — это два ADR.

## Индекс [README.md](README.md)

- Колонка **Status** — только lifecycle-тег; квалификаторы внедрения не дублируются.
- При смене статуса меняются **оба места**: `status:` во фронматтере и строка индекса.

## Инварианты (для quality check)

1. `status:` начинается с одного из четырёх тегов; значение в кавычках.
2. Без `**` и markdown-разметки; скобки сбалансированы, строка не обрезана.
3. Нет `Unknown` / `Working document`.
4. Строка индекса согласована с фронматтером по тегу.
